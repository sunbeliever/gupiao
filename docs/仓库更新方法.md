# 仓库更新方法

仓库：<https://github.com/sunbeliever/gupiao>。维护者`sunbeliever`具有管理员及推送权限，现有SSH方式已通过推送权限预检。HTTPS没有保存命令行登录，不代表GitHub账号没有权限。

## 在本工程继续更新

远程名`origin`配置为：

```text
git@github.com:sunbeliever/gupiao.git
```

仓库保留完整源码历史，并提供以下入口：

- `main`：可浏览的当前源码、制作/验证说明、发布文件与不可变证据快照。
- `fix/auditable-paper-account`：本次专项修复分支。
- `baseline/techscope-1.5.1`：原审查版源码基线，不在此分支继续修复。

本机当前修复分支已跟踪`origin/main`，配置`push.default=upstream`，可以直接更新首页分支：

```powershell
git add <本次确认的文件>
git commit -m "说明这次具体修改"
git push
```

也可以明确指定目标，并按需同步保留的修复分支：

```powershell
git status
git add <本次确认的文件>
git commit -m "说明这次具体修改"
git push origin HEAD:main
git push origin HEAD:fix/auditable-paper-account
```

不要使用`git push --force`覆盖远程历史。多人或多工作区修改时，先获取并核对远程新提交，按实际差异整合。

## 推送范围

已发布的源码、文档、EXE、ZIP及证据目录可更新到新版本目录。`tools/`、普通`dist/`、本机缓存、活动模拟日志及签名材料默认忽略。`validation/`中只有明确选定的旧复现资产和测试夹具被单独纳入版本，不能把整个目录强制添加。

提交前检查暂存文件和历史中是否出现密钥、密码、真实账户信息。不要输出整个环境对象，也不要把工具会话日志当作项目文档推送。

## 发布新版

1. 保持旧发布目录及全部亏损快照，新增`releases/<新版本>/`。
2. 跑相关回归；构建EXE后执行真实原生联网、账户保存与重启验收。
3. 记录新EXE、源码、模型、规则、数据和费用指纹。EXE重建可能产生不同哈希，不使用别次验收假冒本次成功。
4. 将只读证据放入新的日期/实验目录，注明真实截止时刻和未覆盖项。
5. 检查完整包解压后可以复现测试，再更新README链接并提交推送。

当前活动实验已冻结。只修改文档或上传快照，不改变其源、模型、费用、成交与亏损；修改金融规则后的实验必须另用新ID和未来时段。
