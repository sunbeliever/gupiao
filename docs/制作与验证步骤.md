# 制作、运行和验证步骤

当前发布：Windows **1.6.0.1 持续账户审计版**。这是数据分析与虚拟账户软件，投资优势尚未验证。以下步骤不连接券商、不真实下单、不购买服务。

## 1. 直接运行已验证的程序

1. 从[发布文件目录](../releases/v1.6.0.1/)下载完整 ZIP 或 EXE。
2. ZIP 解压后，先关闭旧版本窗口，再双击 `科技观察-持续账户审计版.exe`。
3. Windows 需要 WebView2 运行时。缺少时从[微软官网](https://developer.microsoft.com/microsoft-edge/webview2/)安装。
4. 查看“观察、详情、资讯、回测、模型”五页。参数、K线和历史研究保留。
5. 在“模型”页核对模拟方案、资金、费用和风险限制，再点击“联网更新并继续同一账户”。后续延续账户，不重置亏损。

本机账户保存在 `%LOCALAPPDATA%/TechScopeDesktop/cache`。旧 `paper.current` 只读保留，新持续账户用 `paper.continuous.current`。窗口关闭后不补造离线成交；重新打开延续已存持仓。文件损坏或读取失败会阻止重新开户。

全额方案本金 1 万元，软件最多选择 3 只合格科技 ETF，保留整手和费用余款。小额学习是独立命名方案，最多投资 1,500 元。股票保留行情、参数和研究，当前持续账户仅执行科技 ETF。两个方案不能混算收益。

## 2. 获取源码

```powershell
git clone https://github.com/sunbeliever/gupiao.git
cd gupiao
```

已有推送权限并配置 SSH 的维护者可以使用：

```powershell
git clone git@github.com:sunbeliever/gupiao.git
```

先读 [project-map.md](../project-map.md)。权威开发源是 `assets/`、`windows/` 和 `scripts/`。`evidence/`、`validation/audit-repair/baseline/embedded/` 是发布/验证快照，不在这些副本上修代码。

## 3. 离线回归

原验收环境使用 Node.js 24.18.0、Python 3.12。核心 JavaScript 测试不需要安装 npm 包。

```powershell
node --test tests/*.test.js
python tests/package_release_test.py
node scripts/continuous-replay-check.js
```

已发布版本的结果为 189 项 JavaScript 回归、2 项打包回归通过。8 组人工跨日场景验证逐笔订单、账本、费用、T+1、节假日、退出失败、拆分分红、断网及重启一致性。这些人工数据不是市场投资收益。

历史候选研究测试所需的 `validation/ml-research/current-scores.json` 是明确保留的旧研究夹具，不是当前推荐。

可单独重建旧版 8 项行为检查与内置 2025/2026 报告：

```powershell
node scripts/audit-baseline-reproduction.js
```

这会读取本仓库保留的旧发布资产，在本机 `validation/audit-repair/baseline/` 生成重算结果。原审查的 `reproduce.js`、`reproduce_embedded_reports.js` 没有随附件提供，本脚本是独立重建，不能冒称运行过原脚本。

## 4. 准备 Windows 构建依赖

需要 Windows x64、Windows PowerShell/PowerShell、.NET Framework 编译器及 WebView2 SDK。原验收编译器路径为 `C:/Windows/Microsoft.NET/Framework64/v4.0.30319/csc.exe`。

原验收使用 [Microsoft.Web.WebView2 1.0.3537.50](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.3537.50)。将这个 NuGet 包解压到 `tools/webview2/sdk`，保留其许可证与 NOTICE。构建脚本检查以下路径：

```text
tools/webview2/sdk/lib/net462/Microsoft.Web.WebView2.Core.dll
tools/webview2/sdk/lib/net462/Microsoft.Web.WebView2.WinForms.dll
tools/webview2/sdk/runtimes/win-x64/native/WebView2Loader.dll
```

`tools/` 是本机依赖目录，没有把 SDK、签名密钥或密码提交到仓库。公开 SDK 可自行从官方包获取，无需为运行已发布 EXE 安装开发工具。

## 5. 编译 EXE 并做真实桌面验收

```powershell
New-Item -ItemType Directory -Path dist -Force | Out-Null
& ./scripts/build-windows.ps1
& ./scripts/test-desktop.ps1 -Executable ./dist/TechScope-Windows.exe -Live -VerificationRoot ./validation/desktop-local
```

输出 `dist/TechScope-Windows.exe`。真实验收会使用隔离配置启动两次，检查界面、联网、19 只日线应完成日期、重复启动抑制和亏损账户恢复。只在完整数据满足日历要求时通过；不能以 Node 可联网代替原生 EXE 验收。

原发布证据：43 项原生安全/缓存检查、42 项真实 EXE 检查通过。新电脑重新构建的文件哈希可能不同，需要重新执行自己的验收，不能照抄旧报告的成功状态。

## 6. 理解模拟与费用

- 30 分钟只检查工程运行，结束后持续账户仍持有、估值和请求合法退出。
- 入场前冻结 20 交易日到期、风险退出和目标规则。T+1、明确停牌/拒单或缺价会保留持仓，不能保证止损成交。
- 原19只研究池及11因子岭回归保持冻结，当前执行6只科技ETF中的合格候选；没有换成历史趋势或概率候选。
- 统一费用版本 `cn-paper-fees-v1`，最低5元是模拟假设；可以在开户前按合同配置，不能为某次盈利回改费用。
- 成交是带滑点的假设，没有验证真实盘口排队。预测分数不是已证实的赚钱概率。

## 7. 冻结新的前瞻实验

原发布的实验和账本只读。不要复制仓库中的旧 claim 后重新运行，也不要对已查看历史改选赢家。

新的前瞻必须使用新 ID、严格未来的连续交易入场时段，以及真实测试/原生验收生成且匹配当前 EXE、11个模块、原生网络 helper 的门槛文件。`package-audit-release.py` 是原专项归档环境的打包器，包含旧版1.5.1原文件核验，不能作为任意新电脑一键伪造验收的工具。

```powershell
& ./scripts/build-market-transport.ps1 -OutputPath ./validation/new-native/market-transport.exe
# 先完成本机真实门槛校验，再使用实际门槛文件、EXE及未来时间：
node scripts/continuous-paper-monitor.js --prepare --id <新ID> --entry-after <未来ISO时间含时区> --release-verification <实际门槛JSON> --exe <本次EXE> --native-transport <本次helper>
node scripts/continuous-paper-monitor.js --run --id <新ID> --until <当天有界结束时间>
```

已经启动过的同一账户只能在原进程停止、账本完整且无并发租约时 `--resume`，不得重新 `--run`、删除 claim 或重置本金。保持电脑联网，未运行期间不补记成交。原生 HTTP helper 复用与 EXE 同源的 `DesktopHttp` 和 HTTPS 白名单；免费数据仍可能失败，失败时暂停新风险，已有有效持仓独立估值。

## 8. 生成只读账户报告

```powershell
node scripts/continuous-account-report.js --id <实际ID>
```

报告验证完整 tick 前缀与哈希链，按唯一时间戳输出 JSON/HTML；核对现金、持仓、应收、费用、已实现/未实现盈亏、拒单、过期价、观测回撤和换手。模型最多3只、单ETF对照1只、等权对照6只，风险和费用笔数不同，必须连同实际暴露比较。

当前没有证明70%盈利概率或未来10%—20%年收益。2023—2026已看过的结果保留为历史探索，不重新包装为盲测。新闻目前只提取标题字面事实与风险，全文、财报核验、大模型及新闻入价格预测尚未覆盖。
