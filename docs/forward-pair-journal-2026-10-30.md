# Forward paired journal IO (2026-10-30)

Persistence-only library `scripts/forward-pair-journal.js`; no consumer, scheduler, network, SQLite, account creation API or live engine invocation. The fixed preregistered protocol is unchanged. This is engineering evidence, not forward performance or launch approval.

API: `createJournal(directory, {failpoint} = {})` exposes `acquire()`, `release(token)`, `append(token, {packet, result})`, `recover(token)`, `audit()`. `result` must be the pure engine's advanced result, not its duplicate/no-event result. Calling acquire creates an immutable study claim and exclusive writer lock; callers must enforce activation and frozen source prerequisites before any production use. This API does not grant those approvals. It has no reset, lock takeover, deletion or account funding API. Existing/dead writer locks block acquire. Normal append/release/recover require the token PID and lock PID both to equal the current process PID, plus an exact nonce match. A readable nonce is not authority for another process. Same-process prepared recovery is supported. Dead-process recovery/adoption is deliberately unsupported: it returns manual_review_required and retains pending and lock until a separate explicit host-death review/adoption mechanism is designed and independently approved.

Permanent files: fixed study claim; lightweight hash-linked event entries with quotes/plans/source references; packet objects excluding histories; histories addressed by canonical content SHA256. Only the current checkpoint and pending transaction contain the complete Paper state. Pending is exclusively created, file-fsynced, and binds owner, claim, next state, event and packet reference. Completion verifies prepared packet/history digests and the active verified-prefix tail/checkpoint CAS (or full chain during recovery), writes an immutable event, writes/fsyncs a unique checkpoint temporary file, atomically renames it to latest checkpoint, checks both against prepared hashes, then removes only the byte-equivalent pending owned by the current nonce. Failed temporary files and malformed evidence are retained. Nothing deletes the permanent study claim or reconstructs fresh capital.

Recovery only finishes the original persisted prepared transaction within its original still-running owner process after full chain/digest verification. It never calls live advance, changes Date.now, or recomputes old market decisions. Corrupt/missing/inconsistent artifacts return manual_review_required and remain on disk. No pending and a valid chain returns nothing_pending. `audit()` reports `paperReplay:false` and `accountingReplay:false`: it is a hash/binding/checkpoint audit, not Paper or accounting replay. Source authenticity and economic correctness require separate independent read-only replay and frozen-source review. The journal refuses null/non-object states and rejects nonpositive/non-safe-integer source sequences before storing packets or preparing a transaction. It validates fixed state study/protocol identity and roots; it does not replace the engine's plan/account validation.

Windows file fsync and filesystem atomic replacement are used. Abrupt process exit and filesystem errors are tested; power-loss/filesystem-controller durability and hostile filesystem/symlink mutation are not certified. Complete chain scans run at acquire/recovery/explicit audit; active append reuses the verified prefix with tail/checkpoint CAS as described below. Full production scale resource validation remains required. No recovery from arbitrary deleted/corrupt prepared state is claimed. Once pending is removed, only the latest state checkpoint is kept; full Paper history must be independently replayed from the retained packets by a future explicit read-only replay implementation.

Tests use unique OS Temp fixture directories, retained on failures and successes. All fixture histories/quotes are synthetic. Clock override occurs only inside the existing isolated pure-engine fixture helper, never in journal or recovery. Tests cover concurrent independent processes, real process exit at pending/event/checkpoint boundaries (manual_review_required, pending and locks retained), same-process prepared recovery, live cross-process nonce misuse rejection, injected and actual filesystem rename failures, retained temp/corruption evidence, owner mismatch, CAS/duplicate checks, protocol identity, absent claim, history deduplication, and real pure-engine state persistence. Production accounts, original evidence directory, workers and protocol are untouched; deployment and launch remain unauthorized.

New regression red output is retained in validation/daily-20261030/forward-journal-dev/review-fixes-red.txt; green output contains 25 passing tests. ## Active-lease verified prefix optimization (2026-10-30 evening)

Append now reuses a prefix fully verified when the current owner acquired the lease, or when this journal instance first sees an existing same-process owner token. Every append checks the fixed claim, PID/nonce owner, events directory identity/change stamp, exact latest event bytes and exact latest checkpoint bytes before preparing; completion checks the same CAS again. New durable event and full checkpoint hashes must match the prepared values before the prefix cache is advanced or pending is removed. A regression found post-event tampering could otherwise be cached: the retained red test and correction require pending to remain on that failure.

`acquire()`, recovery and explicit `audit()` still scan the full event/packet/history chain. Explicit audit invalidates the active cache even if it throws, so the next append must establish a fresh fully verified prefix. Successful release invalidates it. Acquisition that finds corruption after making its exclusive lock leaves that lock as evidence and throws; it does not silently delete a lock or offer takeover. Dead-owner handling remains manual and unchanged.

Cached append intentionally does **not** certify that every old prefix file remains unchanged on every tick. Mutation of a non-tail old event file can remain undetected until an explicit full audit; a test demonstrates that boundary. Such an audit must be scheduled separately at startup/recovery/close by the future consumer. The directory stamp detects entry creation/removal, and tail/checkpoint byte CAS detects changes to those current files, but hostile filesystem timestamp manipulation and arbitrary mutation races are not certified. Output remains `paperReplay:false/accountingReplay:false`.

The improvement removes repeated prior-event scans from active appends, not the cost of current data: append still hashes/serializes the full current checkpoint and packet histories, so it costs O(current checkpoint + current histories), plus bounded file reads independent of prior event count. It is not an O(1) claim for the application, and cannot replace the missing accounting replay or complete 44-session production acceptance.

Targeted validation adds seven tests: bounded reads, tail/checkpoint CAS, explicit old-prefix audit, acquisition full audit, mutation after pending prepare, explicit-audit invalidation, and mutation after event/checkpoint write. No production deployment, candidate account, protocol change, or launch authorization is included.
